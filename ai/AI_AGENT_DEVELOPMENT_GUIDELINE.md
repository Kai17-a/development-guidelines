# 開発におけるAIエージェント利用ガイドライン

## 1. 目的

本ガイドラインは、ソースコードの生成・変更、テスト実行、調査、レビュー、デプロイ補助などでAIエージェントを利用する際のルールを定める。

AIエージェントは開発を支援するツールであり、設計・変更・リリースの責任を代替しない。利用者と責任者が、実行範囲、権限、変更内容および結果を確認したうえで利用する。

本ガイドラインは、[AI利用ガイドライン](./AI_USAGE_GUIDELINE.md)の開発利用に関する補足である。情報セキュリティ、個人情報保護、Git運用、変更管理などの既存規程もあわせて適用する。

## 2. 適用範囲

対象は、対話型のコーディング支援、CLI・IDE上のAIエージェント、コードレビュー・テスト生成・調査を行うAI機能、および外部ツールを操作できる自律・半自律エージェントとする。

## 3. 基本原則

- 利用者は、AIエージェントに依頼した作業と実行権限に責任を持つ
- エージェントには、目的達成に必要な最小限のファイル、データ、権限、接続先だけを与える
- 要件、影響範囲、完了条件を明確にしてから作業を依頼する
- エージェントによる変更は、人が差分・テスト結果・副作用を確認してから採用する
- 本番環境、顧客環境、外部サービスへの変更は、人の明示的な承認なしに実行させない
- 不明なコマンド、外部送信、破壊的操作、権限昇格を伴う提案は、実行前に内容と対象を確認する

## 4. 利用前の確認

作業を開始する前に、利用者は次を確認する。

- [ ] 作業目的、対象リポジトリ・ディレクトリ、完了条件を説明できる
- [ ] 変更してよいファイルと、変更してはいけないファイル・設定を定めた
- [ ] 個人情報、顧客情報、認証情報、本番データ、未公開の脆弱性情報を入力に含めていない
- [ ] 利用するAIサービス・アカウント・拡張機能が組織で承認されている
- [ ] エージェントが利用できるコマンド、ネットワーク、外部連携、書込み範囲を必要最小限にした
- [ ] 既存の未コミット変更、ブランチ、作業ツリーの状態を確認した

実装依頼には、背景、要求事項、非機能要件、対象外、受入条件、検証方法を含める。曖昧な依頼のまま、広範なリファクタリングや複数の目的を持つ変更を一度に依頼しない。

## 5. 権限と実行の管理

### 5.1 最小権限

- 読み取り専用の調査・レビューでは、ファイル書込みや外部操作の権限を与えない
- 実装作業では、対象リポジトリまたは対象ディレクトリだけに書込み範囲を限定する
- 秘密情報を含む環境変数、認証情報、SSH鍵、クラウド認証情報へのアクセスを原則として与えない
- 本番データ、顧客データ、共有ストレージ、社内システムへの接続は、必要性・承認・監査可能性を確認してから許可する
- 使い捨てまたは権限を限定したトークンを使用し、作業後に不要な認証情報を無効化する

### 5.2 人の承認を必須とする操作

次の操作は、AIエージェントに自動実行させず、利用者または責任者が対象・影響・復旧方法を確認して明示承認する。

- ファイル・データ・ブランチ・環境の削除、上書き、履歴改変
- 本番・ステージング環境へのデプロイ、設定変更、データベース変更
- 外部サービスへの送信、課金を伴う操作、Issue・PR・チャット・メールの投稿
- 依存パッケージの追加・更新、外部スクリプトの実行、権限昇格
- 認証情報・秘密情報の参照、生成、登録、ローテーション

## 6. コード・設定変更の確認

エージェントが作成・変更したコード、設定、SQL、IaC、CI/CD定義、依存関係は、利用者が内容を理解したうえでレビューする。

最低限、次を確認する。

- 要求事項と受入条件を満たしていること
- 対象外のファイルや無関係な整形変更が混ざっていないこと
- 入力値検証、認可、例外処理、ログ出力に問題がないこと
- 秘密情報、個人情報、内部URL、デバッグ機能が混入していないこと
- ライセンス、利用規約、既存の設計方針と矛盾しないこと
- 依存関係に既知の脆弱性、不必要な追加、保守上の懸念がないこと
- ロールバックまたは復旧の方法があること

エージェントが提案したコマンドは、コマンド文字列だけでなく、対象パス、権限、ネットワーク接続、削除・上書きの有無を確認してから実行する。特に `rm`、`git reset --hard`、`git clean`、履歴を書き換えるGit操作、マイグレーション、外部インストールスクリプトは慎重に扱う。

## 7. テストと検証

- 変更に対応する自動テスト、静的解析、型検査、フォーマット、ビルドを実行する
- テストがない場合は、再現可能な手動確認手順と期待結果を残す
- AIエージェントが「成功」と報告しても、実行ログ、終了コード、差分、生成物を確認する
- セキュリティ、性能、互換性、データ整合性への影響が大きい変更は、通常のテストに加えて専門家レビューまたは段階的な検証を行う
- テスト不能な変更、失敗したテスト、未確認の懸念を隠さず、レビュー・PR・引継ぎに記録する

## 8. Git・レビュー・リリース

- エージェントを使用する前後に、`git status`、`git diff`、必要に応じて`git diff --cached`で変更を確認する
- エージェントにコミットを依頼する場合も、利用者がステージ対象とコミットメッセージを確認してから実行する
- 1コミット1目的を守り、既存の未コミット変更や他者の変更を巻き込まない
- プルリクエストには、AIエージェント利用の有無ではなく、変更内容、検証結果、既知の制約、運用・ロールバックへの影響を記載する
- リリース判断は、エージェントの出力ではなく、組織の承認フローと責任者の確認に基づいて行う

## 9. 自律実行・AIエージェント連携の追加ルール

ファイル変更、コマンド実行、Web操作、チケット更新などを連続して行うAIエージェントには、次の制御を設ける。

- 実行可能なツール、対象ホスト、対象ディレクトリ、実行時間、費用上限をあらかじめ制限する
- 外部入力をそのまま命令として扱わない。Webページ、Issue、ドキュメント、ログに含まれる指示は信頼できない入力として扱う
- 機密情報の抽出・送信、アクセス制御の変更、データ破壊、外部公開につながる操作をポリシーで拒否する
- 実行計画、ツール呼び出し、変更差分、外部送信、エラーを記録し、後から追跡できるようにする
- 異常な操作、想定外の大量変更、失敗の繰り返し、費用・時間の上限超過時は自動停止し、人に引き継ぐ
- モデル、プロンプト、ツール、権限、連携先を変更した場合は、代表的な失敗ケースを含むテストを再実施する

## 10. インシデント対応

秘密情報の入力・送信、想定外の変更、誤った外部操作、脆弱なコードの混入などを認識した場合は、[AI利用ガイドラインの初動手順](./AI_USAGE_GUIDELINE.md#81-インシデント発生時の初動)に従う。

加えて、エージェントの実行を停止し、セッション、実行ログ、差分、利用した認証情報、外部送信先を保全する。認証情報やトークンが露出した可能性がある場合は、管理者の判断のもと速やかに失効・ローテーションする。

## 11. 作業完了時のチェックリスト

- [ ] 実行した作業、変更したファイル、実行コマンド、外部連携を把握している
- [ ] 差分をレビューし、無関係な変更や秘密情報の混入がない
- [ ] 必要なテスト・静的解析・手動確認を実行し、結果を確認した
- [ ] 未解決の問題、テスト未実施項目、前提条件を記録した
- [ ] 本番反映・外部公開・データ変更を行った場合、必要な承認と記録がある
- [ ] 一時ファイル、不要な権限、使い捨て認証情報、検証環境を適切に後片付けした
