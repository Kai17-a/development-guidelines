# AI利用ガイドライン

## 1. 目的

本ガイドラインは、生成AIを業務に活用しつつ、情報漏えい、誤情報、知的財産権の侵害、不適切な自動判断などのリスクを管理するための共通ルールを定める。

生成AIの利用を一律に禁止するのではなく、安全に利用できる範囲と確認手順を明確にし、利用者が迷わず活用できる状態をつくることを目的とする。

本ガイドラインは、情報セキュリティ規程、個人情報保護規程、秘密保持契約、著作権その他の既存規程を置き換えるものではない。これらと矛盾する場合は、より厳しい規程または契約上の義務を優先する。

## 2. 適用範囲

本ガイドラインは、役員、従業員、業務委託先その他、組織の業務として生成AIを利用する者に適用する。

対象となる生成AIには、文章、画像、音声、動画、プログラムコードなどを生成・要約・変換するクラウドサービス、組織内で提供するAI機能、およびAIエージェントを含む。

## 3. 基本原則

- 業務利用は、組織が利用を認めたアカウント、契約、設定および環境で行う
- 生成AIへの入力前に、情報の機密性、個人情報の有無、契約上の制約を確認する
- 生成結果をそのまま正しいものとして扱わず、利用者が内容を確認してから利用する
- 生成結果を利用した業務上の最終責任は、利用者および組織が負う
- 判断に迷う情報は入力せず、定められた相談窓口へ確認する
- 生成AIの機能、利用環境、関連法令や契約の変化に応じて、本ガイドラインを見直す

### 3.1 リスクに応じた管理

利用部門は、用途ごとに、扱う情報、利用者・第三者への影響、自動化の程度、社外公開の有無および利用地域を確認する。低リスクの補助作業には共通ルールを適用し、次の場合は「高リスク利用」として事前評価と責任者承認を必須とする。

- 個人の権利、機会、安全または生活に重要な影響を与える判断を支援・自動化する場合
- 要配慮個人情報、機微な業務情報または大量の個人データを扱う場合
- 顧客、一般利用者その他の第三者に回答・提案・コンテンツを直接提供する場合
- AIエージェントに外部送信、支払、デプロイ、データ更新などの実行権限を与える場合

高リスク利用では、目的と便益、想定利用者、データの流れ、性能・偏り・誤用のリスク、人による監督、停止条件、苦情・事故対応を文書化する。導入前だけでなく、モデル、プロンプト、連携先、用途またはデータが大きく変わる際にも再評価する。

### 3.2 国内での利用

日本での利用は、総務省・経済産業省の[AI事業者ガイドライン](https://www.meti.go.jp/shingikai/mono_info_service/ai_shakai_jisso/20240419_report.html)が示す、人間中心、安全性、公平性、プライバシー保護、セキュリティ、透明性、アカウンタビリティの考え方を踏まえる。個人情報を含むプロンプトを扱う場合は、個人情報保護委員会の[注意喚起](https://www.ppc.go.jp/news/careful_information/230602_AI_utilize_alert/)に従い、利用目的、第三者提供、サービス提供者による学習利用を確認する。

## 4. 利用を認める範囲

次の用途は、入力情報と出力内容を本ガイドラインに従って確認することを条件に利用できる。

- 公開済み情報または社内利用が認められた情報の要約、分類、翻訳、校正
- 文書、議事録、メール、仕様書、プログラムコードなどのたたき台の作成
- アイデア出し、論点整理、調査計画、テストケース案の作成
- 定型作業の補助や、業務改善のための分析・自動化の検討

組織が未承認の外部サービス、個人契約のアカウント、または無料プランを業務で利用してはならない。ただし、管理部門が安全性、契約条件、学習利用設定およびログ管理を確認して承認した場合を除く。

高い影響を与える用途（採用、評価、与信、医療、法務、人事処分、顧客対応の自動決定など）に生成AIを利用する場合は、事前に責任者の承認を得る。人に重大な影響を与える判断を、生成AIだけで完結させてはならない。

## 5. 入力情報の取り扱い

### 5.1 入力できる情報

次の情報は、承認済み環境での利用に限り入力できる。

- すでに一般公開されている情報
- 組織内で共有が認められており、利用サービスの契約・設定上も入力が許可されている情報
- 個人や組織を識別できないよう、適切に匿名化・マスキングした情報
- テスト用に作成した架空データ

### 5.2 入力を禁止する情報

次の情報は、管理部門が明示的に承認した専用環境を除き、外部の生成AIサービスへ入力してはならない。

- 個人情報、要配慮個人情報、認証情報、位置情報その他の識別可能な情報
- 顧客、取引先、委託先から受領した秘密情報および秘密保持義務の対象となる情報
- 未公表の事業計画、財務情報、人事情報、契約情報、ソースコード、設計情報、脆弱性情報
- パスワード、APIキー、アクセストークン、秘密鍵、接続文字列その他の認証・アクセス情報
- 本番環境のデータ、ログ、ダンプ、障害情報
- 法令、契約、社内規程により第三者提供または目的外利用が制限される情報

固有名詞、メールアドレス、顧客番号、正確な数値などを伏せても、文脈の組み合わせで個人や案件を特定できる場合がある。匿名化した情報を入力する場合も、再識別の可能性を確認する。

### 5.3 利用環境の確認

管理部門は、承認するサービスについて、少なくとも次を確認する。

- 入力・出力データがモデル学習に利用されない契約または設定になっていること
- データの保存場所、保存期間、削除方法、再委託先が把握できること
- アカウント管理、アクセス制御、多要素認証、利用ログの取得が可能であること
- 利用規約、個人情報の取り扱い、知的財産権、責任分担が業務利用に適していること

## 6. 生成物の取り扱い

### 6.1 正確性と品質の確認

生成AIは、もっともらしい誤り、古い情報、存在しない出典や機能を示すことがある。生成物を業務に利用する前に、利用者は目的に応じて次を確認する。

- 数値、固有名詞、法令、仕様、引用、リンクは、信頼できる一次情報または公式情報で裏付ける
- 顧客・社外向けの文書は、担当者または責任者が内容、表現、機密情報の混入を確認する
- プログラムコードは、内容を理解したうえでレビュー、テスト、セキュリティ確認を行う
- 重要な判断に使う分析結果は、根拠、前提、偏り、再現性を確認する

### 6.2 著作権・知的財産権・肖像等への配慮

- 特定の著作物、作者、キャラクター、ブランド、人物の作風・表現を不当に模倣させる指示をしない
- 社外公開、納品、販売に利用する文章、画像、コードなどは、既存の著作物や商標との類似、第三者の権利侵害がないかを確認する
- 他者の著作物を入力する場合は、利用許諾、契約、法令上の根拠を確認する
- 引用する場合は、出典を確認し、必要な表示と引用の要件を満たす
- 人物の氏名、顔、声、画像を扱う場合は、肖像権、パブリシティ権、本人同意などを確認する

### 6.3 公開・利用時の責任

生成物を利用または公開する前に、利用目的に必要な承認を得る。生成AIが作成したことを示す表示、利用記録、プロンプトまたは参照データの保存が必要な業務では、各部門の定めに従う。

第三者に対してAIが直接応答・提案する用途では、回答範囲、回答してはならない事項、根拠となる情報源、有人窓口への切替手段を定める。価格、契約条件、法令、医療・金融・人事など重要な案内は、公開前のテストと、運用中の品質監視を行う。

## 7. 開発・自動化での利用

- 生成AIが提案したコード、設定、コマンド、依存パッケージを無検証で本番環境へ適用しない
- 秘密情報をプロンプト、ソースコード、設定ファイル、ログに含めない
- 外部ライブラリやコマンドを提案された場合は、提供元、ライセンス、保守状況、脆弱性を確認する
- AIエージェントにファイル変更、デプロイ、外部送信などの権限を与える場合は、最小権限とし、人による確認地点を設ける
- 自動処理の対象、権限、実行履歴、停止方法、障害時の連絡先を明確にする

## 8. 役割と相談・報告

| 役割 | 主な責任 |
| --- | --- |
| 利用者 | 本ガイドラインを守り、入力と生成物を確認し、問題を報告する |
| 部門責任者 | 業務上の利用目的、承認、教育、生成物の最終確認を管理する |
| AI・情報セキュリティ管理部門 | 利用サービスの承認、設定管理、相談対応、利用状況の確認、ガイドライン更新を行う |
| 法務・個人情報保護担当 | 契約、権利、個人情報、高リスク利用に関する相談に対応する |

利用者は、情報を誤って入力した、秘密情報・個人情報の漏えいが疑われる、権利侵害や誤情報の懸念があるなどの問題を認識した場合、直ちに部門責任者および定められた窓口へ報告する。自己判断で削除・隠蔽・対外説明を行わない。

### 8.1 インシデント発生時の初動

インシデントまたはその疑いを認識した者は、次の順で対応する。

1. 生成AIへの追加入力、外部公開、自動処理を停止し、影響の拡大を防ぐ
2. 入力・出力、利用サービス、アカウント、時刻、対象データ、実行操作を記録・保全する
3. 部門責任者、AI・情報セキュリティ管理部門、必要に応じて法務・個人情報保護担当へ直ちに報告する
4. 管理部門が、利用サービスの削除・隔離・認証情報の無効化、本人・取引先・監督機関への連絡要否、再発防止を判断する

生成AIの画面上で会話を削除しても、外部サービス側の保存や学習利用が止まるとは限らない。削除だけで対応を完了とせず、契約・サービス仕様に基づく削除依頼と影響確認を行う。

## 9. 教育、記録、見直し

- 利用開始時および定期的に、入力情報の分類、誤情報、著作権、承認済みツール、事故報告を含む教育を実施する
- 管理部門は、必要に応じて利用ログ、問い合わせ、インシデント、利用実態を確認し、シャドーAIを抑止する
- 高リスクの利用ケースは、目的、使用ツール、入力情報、確認者、承認結果を記録する
- AIを業務で利用する者には、役割と利用リスクに応じたAIリテラシー教育を行う
- 本ガイドラインは、少なくとも年1回、および利用サービス、業務、法令、契約、インシデントに重要な変更があったときに見直す

## 10. 利用前チェックリスト

- [ ] 承認済みのアカウント・サービス・設定を使っている
- [ ] 入力情報に個人情報、秘密情報、認証情報、本番データが含まれていない
- [ ] 必要に応じて匿名化・マスキングまたは架空データへの置換を行った
- [ ] 利用目的と利用範囲が業務上妥当であり、必要な承認を得ている
- [ ] 生成物の事実、出典、権利、品質を人が確認した
- [ ] 社外公開・納品・本番適用の前に、所定のレビューまたは承認を得た
- [ ] 問題が生じた場合の連絡先と停止方法を確認した
